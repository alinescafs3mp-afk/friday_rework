# Source114: диагностика сохранения истории

Это небольшое публичное дополнение к уже опубликованным изменениям XLSX и vision. Здесь находятся только три финальных файла Source114, их точные исходные версии для воспроизведения патчей и автономные проверки. Каталог не является полной сборкой продукта и не заменяет интеграционную квалификацию.

## Что изменилось

Диагностика сохранения истории различает ошибки подготовки сессии, сбора и построения строк, проверки области видимости, записи, синхронизации маркеров и удаления затенённых checkpoint. Отказ проверки области видимости по-прежнему блокирует запись нового содержимого; уже сохранённая история повторно не фильтруется.

Метаданные ошибки содержат класс и место исключения, но не текст исключения, который может раскрыть закрытые данные. Цепочка исключений ограничена и защищена от циклов. При ошибке импорта диагностического помощника или сбора метаданных сохраняется безопасный отказ, а устаревшая диагностика предыдущего отказа не переиспользуется. Новый ход очищает эти временные данные и связывает их с новым входящим сообщением.

Корреляционный идентификатор вычисляется как SHA-256 от канонического JSON `[session_id, str(platform_id)]` только для допустимых непустых идентификаторов. Отсутствующие или недопустимые значения дают `null`; сырые идентификаторы в метаданные не попадают.

Принятые ранее указания B150 для XLSX (`freeze`, `print_area`, `number_format=0.00`) сохранены. Проверка сравнивает AST и подтверждает, что вне функции `guard_generated_reply` принятая B150-версия `friday_user_scope.py` не изменилась.

## Состав и точные версии

- `source/` — три полных финальных файла установленного Source114; их байты не переформатированы.
- `basis/source113/` — исходные версии двух файлов persistence из Source113.
- `basis/b150/` — принятая B150-версия `friday_user_scope.py`, необходимая только как исходная точка объединённого diagnostic-scope патча.
- `patches/` — три точных unified diff: Source113 → Source114 для persistence и B150 → Source114 для объединённого scope.
- `SOURCE-HASHES.json` — SHA-256 каждого финального и исходного файла и связь с патчем.
- `tests/` и `check.py` — автономные проверки стандартной библиотекой Python.
- `FACTS.json` — отдельные обезличенные факты об установке и границах приёмки.
- `CHECK-RESULTS.json` — результат проверки именно этой публичной копии.

Старые XLSX/vision-файлы, полный source carrier и остальные слои продукта сюда не копируются.

## Воспроизведение

Из любого рабочего каталога выполните:

```sh
python3 -I -B /путь/к/этому/каталогу/check.py
```

Достаточно стандартной библиотеки Python. Проверка читает только файлы этого каталога, сверяет SHA-256 манифеста, заново строит три патча из поставленных исходных и финальных байтов и запускает 23 unit-проверки реальных извлечённых функций. Внешние зависимости заменены синтетическими объектами в памяти. Audit guard запрещает запись файлов, создание процессов и socket-эффекты; результат выводится в JSON, файлы не изменяются.

Это не проверка установленного продукта, модели, Telegram, Office, сети или настоящей базы данных. Число переносимых проверок нельзя складывать с ранее принятыми авторскими и независимыми проверками как будто это новый сквозной результат.

## Факты и границы приёмки

По обезличенным принятым фактам Root, Source114 установлен и связан со свежей native-версией; постоянные Gateway и Dashboard возвращены, а CA login дал HTTP 200. Это отдельные source/native/service факты, не доказательство пользовательского смыслового результата. `fullfresh` остаётся `UNPROVEN_INHERITED8`.

Исходный S13 закрыт как resource-only: результат модели `UNKNOWN`, `full180=false`, первоначальная причина не доказана, старые часы закрыты. Публикация и успешные offline-проверки не означают, что исторический S13 исправлен или повторён. Нового результата S14 нет; runtime/user semantic и полный release не приняты.

Root отдельно проверяет приватность, копирует каталог в документацию и публикует его. Публикация не выполняет установку и не разрешает повтор старых операций.

Сырые приватные receipt, config, credentials, logs, handoff, идентификаторы сессий и пользователей, пользовательские файлы и рабочие доказательства не включены. Уведомление и лицензия Hermes сохранены в `THIRD_PARTY_NOTICES.md` и `LICENSE-Hermes.txt`.
