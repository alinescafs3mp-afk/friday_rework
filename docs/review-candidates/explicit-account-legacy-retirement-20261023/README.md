# Явное завершение старых входов своего аккаунта

Старые Basic AT/RT не содержат идентификатора пары. Для неизвестных друг другу старых токенов реализовано отдельное действие: завершить все legacy-входы текущего подтверждённого аккаунта. Пароль вводится заново, scope подтверждается явно. Современные сессии этого аккаунта и входы других аккаунтов сохраняются; обычный logout сохраняет прежний scope.

[Native API/store patch](native-api-store.patch) добавляет постоянный маркер в существующий authenticated SessionStore и endpoint `/api/auth/legacy-retirement`. [Plugin UI patch](plugin-account-ui.patch) добавляет действие в существующую Friday Administration console через штатный SDK. Передача цели по выбранному Telegram-профилю отсутствует: цель определяет проверенная Dashboard-сессия. Пароль не сохраняется приложением; повторная отправка после UNKNOWN автоматически не выполняется.

Native-патч применяется поверх [канонического decoder-исправления](../admin-basic-canonical-token-20261023/README.md); точные before/after SHA каждого файла приведены в [наблюдениях](OBSERVATIONS.json). Для UI before-SHA — `5496f16fe6b1506a3a234c305aff1843f55e86f118953ff7b191dd5430449e1d`, after-SHA — `d2d290f8e1cea5cc0ba4a99af49aea7c0ec2bdb563a9ebad593aea2b509935a6`. Before соответствует принятому установленному plugin/candidate; опубликованный основной файл имеет другой исторический prefix. Применение требует согласования этого основания с сохранением принятых guards.

Фактическая проверка backend: 11 PASS / 0 FAIL, полные реальные модули и ASGI с synthetic accounts/stores, четыре свежих интерпретатора на одном ledger/anchor. Проверены неизвестные старые AT/RT, ранее созданная alias-lineage, сохранение современных/чужих сессий, migration v1→v2, границы размера, отказ записи и commit с потерянным подтверждением. Независимое ревью выявило крайний случай directory-fsync: повторное подтверждение теперь сначала заново публикует/fsync существующий marker. Исправление получило отдельную проверку, 0 HIGH/MEDIUM.

Фактическая проверка UI: 18 контролей в существующем Chromium с явным hook/DOM fixture и точными функциями SDK. Проверены double-submit, смена профиля/identity, очистка пароля, UNKNOWN и отсутствие автоматического повтора. Это компонентные наблюдения; реальная React SPA ещё не проверена. Независимое ревью: 0 HIGH/MEDIUM; исправлен недостаточный oracle проверки checkbox. Разные группы и версии прогонов не складываются в общий pass count.

Пакет принят в исходниках. Согласованная source-композиция API/UI, установка, реальное действие аккаунта через native React/TLS и полная административная приёмка остаются открытыми. Действие требует сохранения ledger, sibling anchor, signing secret и совместимой версии всех обслуживающих workers. Исходники и локальные проверки не подтверждают live-отзыв. Публикация использует завершённые наблюдения без повторных запусков.
