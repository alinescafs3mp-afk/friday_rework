# DOCX text replacement — completed source review candidate

Status: **UNCONNECTED / NOT_RUNTIME_ACCEPTED**. This archive preserves the complete accepted `docx_common.py` helper and source patches. Integration, installation and ordinary post-install retesting remain pending; the archive does not connect code to an installer or runtime and is not a standalone installation bundle.

`replace_in_paragraph` searches non-overlapping matches in original text, never searches inserted text, and reconstructs each affected run once. This retains termination when replacement text contains the search text or equals it, with the existing policy that a cross-run replacement inherits the first text-overlapped run's formatting. The final source also fixes two defects found in the preceding efficient interim implementation: direct paragraph runs separated by any other XML child are distinct matching segments, and empty or merely boundary-touching runs receive no edit or `Run.text` assignment. Preserved empty runs can therefore retain field/drawing markers instead of being rewritten.

The matching domain is deliberately limited to maximal consecutive direct `w:r` children. Every other direct paragraph child, including hyperlinks, bookmarks and empty wrappers, is a barrier. Hyperlink-internal text and matches spanning containers are unsupported. `Run.text` still removes non-text children from a run whose text has positive overlap with a match; general field/drawing fidelity is not established. XML preservation observations cover tested nodes and no-match paragraphs, not all WordprocessingML, schema validity or Office rendering.

The history matters: the 3,364-byte donor helper was followed by a 4,696-byte efficient interim candidate, which independent review rejected for the two XML defects. The accepted helper is 6,517 bytes and combines the earlier original-text/efficient reconstruction work with the final XML repairs. `SOURCE.json` pins all three versions. `docx-common-cumulative.patch` is the complete donor-to-final patch with canonical relative source paths. `docx-xml-boundary.patch` is the exact implementation-author patch from the rejected interim to the accepted source; its preimage is not the donor helper. Applying either patch requires its exact pinned preimage. The full final helper is included byte for byte.

Independent execution on the exact final helper passed 253 plain-text checks (13 focused and 240 independently computed literal-match/character-ownership checks), with 33 ordinary save/reopen checks. Separate XML barrier and empty-run checks confirmed preserved XML and zero assignments for untouched runs; both original defects were reproduced on the rejected interim as negative controls. The genuine, unchanged `docx_edit.py` CLI used the final helper, reported three replacements, and produced a reopened document with the checked boundaries, preserved empty markers and bold/italic formatting intact. These are focused source observations; test fixtures, expected outputs, harnesses and raw evidence are excluded.

The final helper also completed four independent 65,536-character one-run checks for ordinary, expanding, equal and deleting replacement under the same CPU limits of 1 second soft / 2 seconds hard, a 2-second process wall limit and a 512 MiB address-space limit. Observed helper times were 0.0175–0.0230 seconds and process wall times 0.0833–0.0927 seconds. A separate 6,144-run case with 2,048 preserved empty markers completed under those same limits. Measurements used one CPU with Python 3.14.4 and python-docx 1.2.0; they do not establish a universal complexity proof or performance SLA.

Independent acceptance is restricted to this source and these disclosed boundaries. No installed-product, live, catalogue, full-format or release acceptance follows from the source result. No model or messaging request ran as part of these focused checks.
