# Office semantic predicates — source review archive

Status: **SOURCE_ONLY / UNCONNECTED / NOT_INSTALLED / NO_LIVE / PARTIAL_PREDICATES**.

This archive preserves the unchanged, finite Python standard-library module `office_semantics.py`, its generic API contract, and the locked `semantic-review.schema.json` report format. It is a source archive for review; installation, runtime connection, live execution, product acceptance and release acceptance remain unestablished. No installer, receiver, operational grader, actual report, fixture, prompt, private checklist or expected-output collection is included.

`inspect(data: bytes, format: str) -> dict` reads bounded transitional OOXML `docx`, `xlsx` and `pptx` bytes into a selected content view. `grade_bytes(data, format, requirements, before=None) -> list[str]` compares that view with explicit caller-supplied predicates. Unsupported operations raise `Unsupported`, a `ValueError` subclass; failed comparisons and malformed inputs raise `ValueError`. No document is edited, extracted, opened in Office or sent over a network. Imports use only the Python standard library.

`CONTENT-CONTRACT.md` gives the exact closed requirement shapes, selected content, bounds, normalization and refusal rules. Its examples are generic API notation, not a case matrix or expected answers for private tasks. The original source-preparation label “Private” is retained in the verbatim contract; no private execution data accompanies it. The module contains no built-in case IDs, task-to-requirement mapping, expected document outputs or acceptance checklist: callers supply expected text, cell values, image hashes and preservation selectors themselves. Exposing these parameterized comparison rules does not expose an acceptance oracle for private tasks. A caller still has to establish that its requirements are complete and appropriate.

Supported comparisons cover direct DOCX body paragraphs and tables separately, represented hyperlinks, field instruction strings and referenced image hashes; XLSX sheet order, selected existing typed cells and literal formulas, and represented hyperlinks; PPTX slide relationship order and declared shape-tree text, selected tables, text hyperlinks and referenced image hashes. `preserve.parts` compares selected package-part hashes against supplied before-bytes; `preserve.view` compares selected normalized values. These checks establish only the requested comparisons.

Limits remain substantial. There is no formula calculation, cache-freshness check, field-result computation, Office layout or rendering, visual/visibility evaluation, general natural-language requirement assessment, chart-meaning assessment or full-document preservation claim. DOCX paragraph/table interleaving is not represented. PPTX hidden or off-slide content is not distinguished from visible content. Headers, notes, comments and unselected content have no general semantic acceptance. Byte preservation applies only to the selected existing parts; view preservation applies only to selected normalized values. Parsing succeeds for a finite subset of transitional OOXML; strict OOXML, active content and other unsupported features are refused. A successful selected predicate cannot accept an entire file format, catalogue case, workflow or release.

The unchanged report schema describes bounded report fields and hash/message bindings. It contains no actual run IDs, user IDs, reports or artifact values. Its required verdict and operator-check fields are report syntax; schema conformance does not perform those checks or grant semantic, native or live acceptance. The operational grader and receiver are absent from this archive, so this schema alone is not a working report-verification pipeline.

These are mechanical observations for selected predicates and report/receipt interactions, not unique catalogue obligations, source-wide coverage or a full Office suite. No actual product output, installed workflow or live Office execution is accepted by those counts. This publication review statically inspected the proposed bytes and their privacy boundary; it did not rerun the prior suites.
