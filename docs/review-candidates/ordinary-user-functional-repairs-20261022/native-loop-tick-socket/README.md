# Native loop-tick socket path correction

This separate block publishes the accepted native source correction for a loop-tick liveness witness that could not bind when the product home made its Unix socket path too long. It contains one production-module change and one added test file against native source 111. It is an independent source-only delta: at acceptance it was not installed or runtime accepted. This publication does not compose it into source 112, install it or check the live service. Full product scope remains open.

The shared producer/probe path helper preserves existing short addresses and chooses a bounded per-home/per-user private temporary namespace for long paths. Producer and actual CLI probe resolve the same address. The correction checks directory and socket ownership/type, refuses unsafe namespaces without broadening their permissions, preserves live or uncertain nodes, and removes only the exact owned socket identity during cleanup. Stale-node sweeping requires a positive ASCII PID and proof that its process does not exist. The existing native Windows TCP branch remains unchanged. The same-user host process remains the trust boundary.

Root accepted the final whole production diff and added tests after independent source review; the original author's 44 passing controls and lint result are reused without another run. Those controls included real isolated Unix listeners and the actual CLI probe, the original long-path bind failure, multibyte paths, producer/probe parity, unsafe namespace refusals, live-node preservation and cancellation cleanup. One native Windows test was skipped on Linux; no Windows execution is claimed. Disposable isolated loopback tests establish source behavior, not installed product or user acceptance.

Publication packaging separately checks zero-fuzz application to the exact source-111 beforeimage, byte identity with the accepted production and test afterimages, Python parsing, and reverse restoration. Temporary verification copies are removed. The [manifest](patch-manifest.json) pins the exact patch and evidence; [STATUS.json](STATUS.json) separates source, installation and runtime facts. No project settings, product home, credential, service, native queue, model or prior consumed operation was changed by this publication. GroupChat's separate authorization gap remains described in the [confirmation and GroupChat status block](../native-slash-confirm-anchor/README.md).
