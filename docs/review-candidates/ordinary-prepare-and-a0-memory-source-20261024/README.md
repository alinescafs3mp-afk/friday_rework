# Ordinary prepare history and optional A0 memory: source-only changes

This package preserves the completed R223 and R225 source changes and their prior offline results. It performs no installation, service operation or runtime acceptance. At the supplied preparation snapshot, Source120 did not contain these future source fixes. The S230 canonical six-file installation scope combines patches 0001 and 0002. **Optional memory in patch 0003 is excluded from S230 installation.** This publication package does not establish a later installed version.

`0001-ordinary-prepare-history.patch` changes five modules. Each ordinary prepare invocation gets one local immutable-history walk under its original 180-second budget. Only complete successful graph proofs can be reused inside that invocation. Current publication/source bytes, mirrors, launcher, native registration/unit identity, authority and configuration checks stay fresh. Standalone calls get fresh walks. Prior results: 25 focused controls passed and independent source review accepted the unchanged bytes. These controls use explicit full-history/native stand-ins; actual full-graph cost and whole prepare180 fit remain UNKNOWN.

`0002-current-guard6-record-parity.patch` changes only record identity reconstruction to match the existing guarded current plan producer. It includes no optional-memory changes. Three current producer variants passed and nine correctly repinned clock/resource negatives were refused; Root independently accepted the source delta. Native and network observations in those checks are offline fixtures.

`0003-optional-a0-persistent-memory.patch` contains the separate six-module optional memory implementation and applies after 0002. Configuration remains absent by default. Successful jobs can preserve sealed per-user/per-lineage memory and embedding-cache bytes while workspaces, uploads, routes, grants, clocks and authority remain fresh for each job. Lineage includes the declared embedding dimensions and revision; declarations are not live model observations. The native memory guard is unchanged and the host does not unpickle. Fourteen focused checks and two additional independent negative controls passed previously; synthetic native/network/FAISS observations are explicit fixtures.

The optional memory implementation is source-only and uninstalled. Host cancellation or recovery can bypass the adapter callback, leaving changed bytes quarantined; no automatic adoption, replay or overwrite is provided. Native startup/mount compatibility, actual native vector creation/load, hostile-pickle semantics and useful cross-job recall remain unaccepted. **Warm runtime reuse is not implemented:** the adapter still stops after a response and the runtime still creates job-specific containers and authority; native process/session state is not preserved. RAM, startup and stop limits are preserved; vector dimensions are not RAM capacity.

Patches are relative to a candidate product source root containing `plugins/` and `scripts/`, not necessarily the current public repository HEAD. `FACTS.json` pins every exact before/after source SHA-256 and patch SHA-256. Apply only to matching input bytes, in the recorded order, in an owned source checkout. Patch 0001 intentionally has zero unchanged-context lines to omit a private host path from the original diff without changing the source delta; Git application requires `--unidiff-zero`. Patches 0002 and 0003 are byte-for-byte copies of the accepted source patches. Optional patch 0003 is a future integration choice and must remain separate from S230 scope.

For this publication, exact source pins and in-memory patch reconstruction were checked. Completed implementation tests and reviews were reused without rerunning them. `SHA256SUMS` covers the public payload. Private paths, configuration, identities, credentials, raw logs, vectors and handoff material are excluded. No installed, runtime, semantic recall or full-release success is claimed.
