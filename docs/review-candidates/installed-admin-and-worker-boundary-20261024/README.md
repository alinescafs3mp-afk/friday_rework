# Installed source, scoped administration and worker import boundary

This package records completed observations from R231, R229 and R234, and preserves the accepted R235 five-file source patch. These are separate results: **R231 accepted installed source; R229 accepted one scoped administrative disable and restore; R234 recorded one failed worker preparation; R235 is source-only, uninstalled and unaccepted in live use.** Publication does not establish the current state of a running installation or full-release acceptance.

R231 completed one bounded source installation and accepted the actual installed bytes. Its composition contained 120 native source layers, 316 project files and 47 plugin files. The installed-source verifier passed, with no open high or medium finding in that acceptance. An initial capture refusal concerning owned artifact permissions and an initial verifier execution-environment failure remain recorded; corrected metadata and the correct user service context allowed completion without replaying the installation. This accepted project/source identity, not worker preparation, qualification or runtime behavior. Gateway, Dashboard and workers were off at closure. Previously accepted ordinary document operations were neither rerun nor regraded.

R229 actually disabled an owned test user once, reconciled the resulting state, and restored that user once: two product user-state writes in total. A row-order assertion failed even though the expected state matched when keyed by user; reconciliation confirmed the access-generation change and preservation of unrelated state. The disable was not repeated. The restore passed 23 checks, left the user enabled and retained the advanced access generation. The initial render refusal caused no changes. One initial session-revocation observation remains UNKNOWN because an HTML response could not be parsed as JSON; it was not retried or relabeled as success. Separate subsequent revocation checks returned HTTP 401. This is scoped administrative acceptance. Two actual authenticated product-user actors, stale-transport denial, ordinary user functionality after restore, private-data isolation and full administrative/release acceptance remain unaccepted.

R234 made exactly one actual normal-native worker prepare request, which returned HTTP 503. It was not repeated, and qualification was not admitted or run. Read-only reconciliation found unchanged state/users and checked home/configuration/source-marker identity, with no affected owned worker artifacts. Gateway, worker and jobs did not start; Docker was inactive. The original client/backend preparation lifecycles closed, and the owned Dashboard service was confirmed stopped with its listener absent. These observations cover the affected owned namespace. A complete before-list of the global preparation directory was unavailable; legacy names are not evidence of new effects. The exact server exception was not observed because the API masks exceptions. The import-boundary explanation remains a hypothesis for that particular HTTP 503.

`0001-worker-native-module-boundary.patch` preserves the exact accepted R235 delta in five existing plugin modules. It resolves canonical product helpers through existing installed source/ownership checks and a request-local module graph. Product scripts and two rendering helpers retain a shared helper/type identity without changing native module search paths, native module identities or the Dashboard API. Preparation retains its original 180-second budget and passes one history walk through final validation; qualification retains its original 300-second budget. The native runtime's 120-second limit is unchanged. The accepted source inventory remains 316 project files and 47 plugin files; no product files are added, and native source and API bytes remain unchanged.

Prior R235 real offline controls loaded a 12-module private helper closure, preserved canonical installer/history-walk identity, exercised renderer/worker-web round trips, preserved native namespaces and discarded request scope. Changed pins, unknown helpers, foreign history types and expired original budgets were refused. Independent source review reported zero open high or medium findings. These results are reused, without a new implementation review or product test. Three native dependency files were joined to genuine source bytes; this was not a full native context. Installed ownership admission, actual normal-native preparation, whole original prepare-budget fit, qualification and useful worker jobs remain unaccepted. The patch does not prove the cause of R234's failure.

The patch is relative to the exact candidate product root containing `plugins/`, not an arbitrary public repository HEAD. `FACTS.json` pins all five before/after SHA-256 values. It uses zero unchanged-context lines to omit unrelated private context from the original diff while preserving every source change; Git application requires `--unidiff-zero`. Apply only to matching input bytes in an owned checkout. This publication preparation applied the patch to an isolated copy of only those five baseline files and confirmed byte-for-byte equality with the accepted R235 outputs, then removed that copy. It performed no installation, service, native/API, model or network operation. `SHA256SUMS` covers the public payload. Private host paths, identities, credential names, addresses, configuration, raw logs and handoff material are excluded.
