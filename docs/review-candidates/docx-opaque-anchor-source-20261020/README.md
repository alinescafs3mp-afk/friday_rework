# DOCX replacement: preserve opaque XML anchors

Status: **UNCONNECTED / NOT_RUNTIME_ACCEPTED**. This source archive extends the earlier [DOCX replacement candidate](../docx-text-replacement-source-20261020/README.md). It does not install or connect the helper to the product. Integration and ordinary post-install retesting remain pending.

The earlier helper preserved empty runs, but replacement in a run with positive text overlap could still remove field markers, drawings and other non-text children. This helper edits only affected text-bearing children and leaves opaque XML nodes in place. A subsequent cross-run defect was found and corrected: retaining the nodes alone was insufficient when moving replacement text across a field-end marker changed field membership.

Matches crossing an opaque boundary now distribute replacement text across the original character slots and runs. Each boundary retains its relative replacement offset, clamped to the replacement length; expansion belongs to the final matched character. This retains the original styles on either side of the boundary. Equal opaque-spanning replacements leave the paragraph XML unchanged. Contraction or deletion may collapse boundaries to the same visible offset without moving, removing or reversing their nodes. Ordinary matches that cross no opaque boundary retain the first positively overlapped run's formatting.

The matching domain remains maximal consecutive direct `w:r` paragraph children. Every other direct paragraph child is a barrier. Hyperlink-internal text, nested text containers and matches spanning containers remain unsupported. Matching uses original, non-overlapping occurrences; inserted text is never rescanned. Empty or otherwise unaffected runs and text children receive no writes.

Independent review accepted this exact source. The checks passed 598 main cases (including 500 randomized cases), 300 ordinary-formatting cases and 21 multiple/nested-field cases. Five variants of the previously failing balanced-field document passed through save/reopen. A manually injected version of the old membership corruption was detected as a negative control. The unchanged `docx_edit.py` CLI reported four replacements, and its reopened output retained checked fields, image relationships and barrier XML. Four 65,536-match cases passed the original CPU limits of 1 second soft / 2 seconds hard, 2-second wall limit and 512 MiB address-space limit; representative many-run and many-child checks had a separate functional budget. Qualification details are recorded in `SOURCE.json`. Private fixtures, expected outputs, harnesses, checklists and raw evidence are excluded. Source checks do not establish installed-product, live, catalogue, full-format or release acceptance. No model or messaging request is part of these focused checks.

Field observations cover balanced complex fields and cached text membership through real DOCX save/reopen. They do not establish field recalculation, arbitrary field semantics, WordprocessingML schema certification, Office rendering or grapheme/layout preservation. Text mapping is pinned to python-docx 1.2.0. Parser preservation of arbitrary extension nodes is not a claim that every synthetic XML fixture is schema-valid.

`docx_common.py` contains the complete source. `docx-opaque-anchor.patch` applies only to the exact 6,517-byte helper pinned in the earlier archive, with canonical native source paths. Applying the patch requires that preimage; the archive is not a standalone installation bundle. Source history and remaining boundaries are explicit in `SOURCE.json`.
