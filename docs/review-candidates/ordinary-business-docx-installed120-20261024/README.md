## Почему исходная семантическая проверка была красной

На тех же байтах первая версия checker дала51/56: она приняла определения tab-stop в стилях Header/Footer/MacroText за текстовую табуляцию, запретила связь строки «Количество:24 комплекта» с единственным явно указанным изделием и заказом в непосредственно предыдущем абзаце и не распознала допустимое свободное заключение с благодарностью. Последний отказ каскадно ломал подпись и порядок частей. Это три ошибки oracle, а не пять новых дефектов документа.

Исправлен существующий checker. Сохранены ограничения ZIP/XML/CRC/размеров/DTD/entities/styles, отказ скрытого/неподдерживаемого текста и inline-tab, реальные абзацы, все факты, значения, роли и отрицательные проверки противоречий. Перенос связи количества разрешён только для единственного изделия в завершённой соседней order-clause и ограниченного денежного/VAT хвоста. Неизменные исторические controls не изображаются повторно выполненными.

Root отдельно повторил только readonly оценку изменённым checker на исходном immutable полученном файле:56/56PASS. Повторной генерации, send, model request или capture не было. Все исходные FAIL receipts и прежние R116/R136 неудачи сохранены. `117` в имени нового файла — историческая обязательная грамматика существующего tester; actual tuple120/P316 привязан отдельно.
