# Native React and actual ASGI: scoped functional observations, 2026-10-24

The existing native React application rendered the Source120 account-retirement UI and exercised the actual complete native ASGI application in an isolated synthetic account/home environment. The final browser run passed **22 of 22 assertions**; a separate direct backend run passed **five groups**. These overlap in behavior and are not 27 distinct semantic controls. Independent review accepted the exact final evidence with **zero open high or medium findings within its review scope**. No product source fix was made by this work.

The frontend used the existing compiled App, BrowserRouter, plugin discovery/registry and lazy PluginPage with **React 19.2.7 / SDK 1.1.0**. All 57 copied static assets matched their pinned bytes. The final direct run imported 355 native modules and the final browser-backed run imported 606, each matched to the canonical source map, with no native-origin errors. These import counts do not mean that the complete native file tree was installed or executed. Existing compiled-byte identity was checked; rebuild equivalence was not established.

Actual Basic password login supplied native cookies and the real authenticated identity. Fresh password and explicit confirmation were required for the self-scoped retirement request. Same-tick double submission generated exactly one successful retirement POST. The self legacy session then received 401; the actual browser-login session and a seeded modern session retained 200. The synthetic second account, beta, retained legacy and modern 200 in a **sequential genuine provider-registry control**, after which the first provider was restored; this does not accept a concurrently configured multiaccount host. Wrong fresh password (401), invalid scope (422) and wrong Origin (403) left exact ledger and anchor bytes unchanged.

Internal navigation cleared password and confirmation; pagehide and actual lazy-router unmount cleared password. A separate mount **after confirmed retirement** performed genuine durable idempotent re-publication and injected acknowledgement loss, producing 503. The UI showed UNKNOWN, cleared the password, retained UNKNOWN across internal navigation and blocked attempted resubmission without automatic retry. This newly observed case concerns an already-retired account; it does not establish first-ever retirement under acknowledgement loss.

Browser page requests were intercepted: exact cached static bytes were fulfilled locally, while HTML, discovery, authentication and API responses came from the actual ASGI application through a stdin bridge. No successful API/authentication response was manufactured. Only the backend entered the private bwrap network namespace. Host Chromium used route interception and background-network-disable flags; one external Docs iframe request was aborted. Browser kernel isolation and blanket background-network isolation were not established. Browser/context/Playwright close completed without recorded error; the browser PID was not separately captured.

The synthetic plugin directory omitted the product plugin API module, so the profiles endpoint returned a real 404. Native bundled achievements/kanban assets also returned real 404 responses; all **15 final browser 404 responses** remain part of the observation. Product-profile and full administrative journeys were not accepted. Two earlier frontend harness failures remain recorded: an oracle omitted the native profile query, then an immediate unmount oracle raced the lazy router. Both occurred before retirement mutation. The first harness path was briefly edited and restored, so continuous immutability is not claimed. Historical smoke-worker/config working paths changed and their original whole source bytes are unavailable; hashes and process/import observations remain forensic evidence. The final versioned sources and final execution freezes were exact. Earlier smoke and reused component/backend counts are not added to this run.
