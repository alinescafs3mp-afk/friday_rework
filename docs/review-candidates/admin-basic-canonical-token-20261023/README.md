# Каноническое кодирование старых Basic-токенов

Пять строк в `_unsign` закрывают воспроизведённый обход отзыва legacy-сессий через другое текстовое представление тех же подписанных байтов. Отзыв использует digest текста токена; decoder теперь принимает только каноническое URL-safe base64, которое выдаёт штатный генератор.

[Патч](canonical-token.patch) применяется поверх [предыдущего исходного исправления отзыва](../admin-basic-session-revocation-20261023/README.md). Исходный файл: `1c584ce738716a3f61c7752cbe97ec795794cb860688838a33f6d7e4422d302a`; результат: `fa61fc89f4c1f0b72c08abbfe29776aa14efeaf278a5cabb7e2d901cd07c5f2e`. Остальные три auth-файла не меняются. Signing secret и штатный генератор токенов сохраняются.

[Наблюдения и ограничения](OBSERVATIONS.json) сохраняют исходный FAIL: четыре альтернативных написания обходили legacy-отзыв. Финальный набор содержит семь проверенных функциональных групп и два ожидаемых наблюдения незакрытых продуктовых ограничений; ноль неожиданных FAIL не означает полную гарантию отзыва. Изменённая граница получила независимую проверку, 0 HIGH/MEDIUM в этом узком срезе.

Старые SIDless-токены содержат subject, вид и срок действия, но не связь между AT и RT. Отзыв одного такого токена не позволяет найти неизвестную пару. Полная гарантия для всех старых входов выбранного аккаунта требует отдельного явно названного действия с более широким scope; обычный logout здесь не расширялся. Глобальный logout, ротация секрета и догадки по TTL не применялись.

Это принятые исходники. Согласованная замена ещё не установленной Source119 готовится отдельно. Установленной остаётся принятая Source118; установка этого auth-исправления, browser/TLS/live и полная административная приёмка здесь не заявляются. Публикация использует сохранённые наблюдения и не повторяет завершённые прогоны.
