# Reviewed Source proposals: configuration work and slow-provider reporting

These are uninstalled review candidates. They are outside product/build wiring and confer no installation, runtime, provider parity, configuration-capacity or release acceptance. The existing full-suite archive-group timeout remains red.

The native configuration proposal avoids regex dispatch for exact literal strings and deepcopy dispatch for exact string keys. The native/project admission proposal reads one current policy per session predicate while preserving subsequent operation/provider checks and the additional dynamic `self.profiles()` veto. It reduces the standard successful authority-check fanout from seven policy reads to four. The per-admission snapshot changes the observation points; it does not claim atomicity across user/environment/managed sources or arbitrary permissive subclass equivalence.

Validation: 65 extracted-function controls, 42 synthetic admission-expression controls, and independent static reviews. An unprofiled synthetic clone benchmark saved about 0.31 seconds over 3,082 own transforms. It establishes neither target setup performance nor closure of the suite timeout. Current file reads, parser/cache bounds, managed/environment evaluation, interoperation admission, provider verification, expiry, CAS, generation and isolation boundaries remain required.

The separate provider-runner proposal bounds each original network call by the original remaining/request limits and ten seconds. A slow request consumes the attempt, halts remaining sends and reports a safe owner-decision event after native cleanup. Uncertain cleanup remains `STOP_UNCONFIRMED`; no request is resent. Normal PASS schema and original four-body protocol remain unchanged. Validation comprises 294 own fake controls, a bounded real signal on a fake blocking action, and independent Root static review; no network, credential, model, helper or issuer execution occurred.

The patches target two native files, one project file, and the private provider-runner Source respectively. The provider diff omits its original host paths. They are publication artifacts, not an apply command. An exact legitimate successor, integration review, real changed-scope checks and the coherent full final gate are still required. The provider runner still requires genuine accepted installed/source bindings and its literal current Source100 contract; a different native successor requires a validated port. Private execution packages, credentials, serving identity, acceptance checklists and oracles are excluded.
