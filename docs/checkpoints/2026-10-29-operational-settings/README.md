# Настройка поиска: реальное действие в прежней Telegram-беседе

Срез 29.10.2026, Source92 и native98. Оператор через действующую административную панель отключил `session_search` для одного пользователя. Следующая обычная Telegram-задача в существующей беседе получила честный ответ о недоступности поиска. Фактические native catalog/search/description не предоставляли этот инструмент; обхода через файлы, веб или worker не было. История и SID сохранились.

Gateway затем один раз штатно перезапущен под прежним постоянным управлением; Dashboard продолжал работать. Второй настоящий запрос в той же беседе подтвердил сохранение запрета. Проверяющий остановил приём на фразе «не могу» в ожидаемом отрицательном ответе. Продуктовое наблюдение принято по тому же аутентифицированному Telegram-ответу и native-интервалу; исходный STOPPED и неполное окно 180 секунд сохранены. Запрос не повторялся, завершённое окно ему не приписывается. Узкая правка существующего checker разрешила отдельный последующий сценарий, сохранив прежние записи и неподтверждённый локальный processing marker.

Настройка возвращена через ту же панель. Реальные HTTP ACK, UI readback, три согласованных файла и действующий DSH consumer подтвердили восстановление. Следующая обычная задача в прежней беседе действительно выполнила `session_search`: сначала поиск, затем metadata browse трёх последних других бесед. Владельцы, даты начала по Москве и все возвращённые ссылки сверены с фактическими результатами и базой текущего профиля. Ответ получен в Telegram; полное окно 180 секунд и terminal drain подтверждены. Изолированный тест не заменял этот пользовательский путь. Собственная тестовая админская сессия отозвана, прежний cookie отклонён сервером.

Первое отключение имело потерянный HTTP ACK при фактически завершённой записи. Оно сверено чтением того же ресурса и исходными before/after, без второго PUT. Восстановление получило настоящий ACK. Исходные UNKNOWN/отказы, clocks и завершённые эффекты не переписаны. Подготовка, запись, запуск сервиса, ответ и наблюдение являются разными интервалами; вложенные интервалы не складываются.

Эта приёмка относится к настройке и трём указанным обычным запросам. После восстановления второго перезапуска не выполняли; кликабельность `@session` в Telegram не доказана. Полная административная изоляция двух управляемых пользователей и отмена реально работающего worker остаются отдельными незавершёнными проверками. Предыдущий worker-сценарий завершился TERM без доказанного пользовательского успеха; его не переигрывали. Ранее принятые DSH coding, выборочная доставка и продолжение сохраняются. Исправление чтения committed association state независимо принято только в исходниках и ещё не установлено. A0 отложен по решению владельца. Полный продукт не READY.

Приватные конфигурации, cookies, личности, SID, raw Telegram/native сообщения и installation-specific bridge в эту публикацию не входят. `FACTS.json` содержит только обезличенные результаты и SHA исходных рабочих свидетельств.

## Последующая дельта DSH

Канонический `Associations.get` теперь читает целый committed-документ через существующую native/operator транзакцию, не ожидая составной блокировки записи. Проверки владельца, каталога, admission marker, native lock и CAS сохранены; snapshot и изменяющие операции сохраняют прежние блокировки. В канонический вариант отдельно перенесена принятая установленная дельта, с сохранением `storage_readonly`, operator-контекста, бюджетов и `NativeCommitUncertain`. Шесть целевых проверок затронутых потребителей прошли; неизменный прежний набор не запускали повторно.

В установленной системе Source93 действительно закоммичен без native-переустановки. Свежая последующая проверка обнаружила отдельный дефект проверки происхождения: исторический SHA ассоциаций читался из уже обновлённого рабочего файла. Этот отказ сохранён; установка не повторяется. Устраняется только перевод этой ссылки в настоящий архив beforeimage с проверкой исходной identity-связи. Возврат постоянных служб и настоящая административная отмена остаются отдельными незавершёнными действиями на момент этого дополнения.

Исходный новый тестовый input с искусственным `sleep(120)` отклонён до отправки. Его исправленный конечный одноразовый источник не содержит задержки. Проверка отмены требует реально работающего DSH; раннее завершение не считается проверкой отмены и не вызывает автоматического повторного запуска.
