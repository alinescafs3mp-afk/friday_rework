# Future derivation, separate policy and typed selector source

These files preserve exact safe source spans from the accepted future consumer
cascade. They are excerpts, not a full installable package. The comments marking
excerpt boundaries, this note, the source index and the controls program are
new publication material. The comparator function itself and every marked source
span retain their exact accepted bytes. Missing names in text excerpts are
intentional: no private pin or operational input has been replaced with a
plausible public value.

The generic derivation family and the policy family remain separate. Generic
derivation has seven slots. The extended policy family has nine: its first seven
authenticate preceding provenance and closure, while only its final two are
bound into the policy receiver. The original seven receiver literals remain
`None`; consumed derivation authority is not appointed again by the policy
extension. The excerpt selects those final two after the existing admission
check. The delivered source starts with all nine literals absent. The generic
factory is not a substitute for the separate policy factory.

Preparation remains distinct from dispatch. Both future preparation entry points
reject absent inputs before loading sources. Genuine preceding committed outputs,
fresh current-state observations, the separate future policy transaction and
qualification still have to join at their existing consumers. Source references
propagate through the selected qualifier, its maintenance helper, authentication
entry, native runner, launch template and outer process. Accepted earlier source
checks covered that reference cascade; this publication does not execute it.
No actual future proof, receipt, grant, clock, current authority, policy effect or
qualification result is supplied here: all remain `null`.

The first selector compared a selected constant snapshot using ordinary equality.
Python treats `1`, `True` and `1.0` as equal, including in nested dictionaries and
container keys. An in-place change can therefore preserve both container identity
and ordinary equality. That defect is retained as an observation. The typed
successor first requires the same concrete type, then compares dictionary keys
and values, sequences and set elements recursively. Its constant guard still
requires the original module/global object identities and exact constant
inventory. Only the new selected-constant snapshot comparison changed; other
verifier comparisons remain unchanged.

Run the new pure controls from this directory:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B typed-selected-literal-controls.py
```

The controls execute only the adjacent exact comparator. They cover unchanged
nested values, both directions of boolean/integer/float substitutions, dictionary
and tuple keys, set/frozenset members, container type and length changes, list
order, same-object nested mutation and restoration. The fixtures are synthetic
literal examples, never operational requests. The comparator is scoped to the
selected finite built-in literal snapshots; it is not a general verifier for
arbitrary objects, recursive cycles, custom equality or nonfinite floats.

`CASCADE-OBSERVATIONS.json` records these new controls separately from reused
source checks. It does not establish native execution, installed compatibility,
recovery, derivation, policy admission, qualification, worker execution or a
returned Telegram artifact. Full modules and pin assignments, host/profile
bindings, archive descriptors and operational values are omitted wholesale.
