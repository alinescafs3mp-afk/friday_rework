Read-only daily-period finalizer (Python standard library, Linux)

  python3 daily_finalizer.py --repo /path/to/public-repository \
    --base FULL_PREVIOUS_DAILY_COMMIT --end FULL_SOURCE_CUTOFF_COMMIT \
    --output /path/to/new-staging-directory

Both commits must be full lowercase object IDs; base is exclusive and end is
inclusive. Base must be an ancestor of end. The parent directory must already
exist and be canonical. Output must be a new directory outside the repository,
worktree and Git metadata; existing directories and symlinks are refused.

The three output files use the reviewed daily index, integrity, and manifest
schema names. Files are exclusively created, SHA256/length verified, then set
read-only (0444; directory 0555). This provides a no-overwrite workflow and hash
binding, not an operating-system immutable flag or protection against an owner
deliberately changing permissions. An interrupted write may leave an incomplete
directory; inspect it and use a different new directory for another run.

Exit 0 means inventory generation passed; it does not mean daily publication or
runtime acceptance. Link gaps remain explicit in publication-integrity.json and
the index, with a PASS_WITH_LINK_GAPS integrity verdict. Invalid/nonancestor IDs,
bad public manifest/hash assertions, manifest coverage errors, unsafe output or
output collisions exit 2 before creating the output directory. No source code
from the inspected repository is imported or executed.

ordered_commits preserves exact parent IDs and per-parent changes in topological
order. Every before/after blob has Git object ID, SHA256 and byte count. Renames
are deliberately represented as deletion plus addition. changed_paths is the
union of all touched paths, including changes subsequently reverted, renamed or
deleted; each has exact commit references. Its status is the base-to-end status
or INTERMEDIATE_ONLY. net_changed_paths separately preserves the base-to-end
diff. Historical outcome bytes remain pinned by these references; their claims
are never rewritten as current acceptance. Merge commits include each parent
edge, so counts can include paths absent from the final net diff.

Public validation examines final touched JSON/Markdown blobs and unchanged
enclosing MANIFEST.json files. It checks reviewed files-list and flat-map
manifests, payload coverage, public SHA256/byte references, inline Markdown
destinations, and explicit local JSON references. logical_source is a provenance
namespace label, not a public link. Original/private provenance hashes, external
URLs, anchors, reference-style Markdown, semantic status ordering and full
privacy review are outside this check. Daily-index historical range fields are provenance
bound by their report manifest, not current-cutoff hash or link assertions.
The typed daily index requires a current integrity_artifact reference. Missing
objects, missing targets, invalid paths/hashes and wrong byte counts are refused;
that reference never falls through to the generic provenance heuristic. The report states these limits. Git
symlinks are inventoried as blobs; their filesystem targets are never opened.

All Git invocations use --no-optional-locks and GIT_OPTIONAL_LOCKS=0. Blob reads
are batched. Replacements, lazy fetch, external diff, textconv and signature
display are disabled; global/system Git config is excluded. The CLI caps its
address space at 1 GiB, affinity at two existing CPUs, and finite Git commands
at 60 seconds each within an 890-second deadline. No background handles remain.

At the 21:00 checkpoint, retain the previous actual daily base, reconcile and
publish source blocks using the existing integrator workflow, then select the
exact source cutoff SHA and run into a new staging directory. Review the final
report, privacy and exact bytes before publication. Record the later publication
commit and verified remote SHA separately; the report cannot include its own
future publication commit in its source range. Every generated artifact remains
PROVISIONAL_NOT_DAILY_COMPLETE with runtime/product/publication authority false.

Focused local tests (write actual temporary Git repositories beside the tests):

  python3 test_daily_finalizer.py

The tests cover incremental windows, manifest hashes, unchanged manifest owners,
dirty worktrees/index stability, intermediate-only add/rename/delete, merge
parent edges, bad lineage/IDs, output collisions and repository-output refusal,
truthful link gaps/provenance labels, empty ranges, root manifests and NUL-safe
Git path parsing. They are finalizer checks, not product, native or live suites.
