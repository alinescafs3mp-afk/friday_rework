Offline Source82 native web tests; these assets are separate from the two-file
production overlay. Do not run them in an installed user home.

Requirements:
  * Python with the native Hermes dependencies, pytest, httpx and requests.
  * An exact disposable composed native source tree containing Source81 and
    Source82, including its bundled plugins/web provider dependencies.
  * The published project tree containing tools/configure_local_test.py and
    its normal project dependencies.
  * Linux fork support for the two journey cases.

Publish only this instruction file, portable-test-bootstrap.py and
source-tests.patch. Keeping native cases in a patch avoids collecting them in
the project's ordinary pytest suite.

Set explicit paths to FRIDAY_TEST_PYTHON, FRIDAY_TEST_NATIVE,
FRIDAY_TEST_PROJECT and a new private FRIDAY_TEST_SANDBOX directory. Set
FRIDAY_WEB_TEST_ASSETS to this asset directory, create a cases directory below
the sandbox and apply source-tests.patch there with git apply. The patch creates
exactly four test/fixture files; it contains no production changes.

  mkdir -p "$FRIDAY_TEST_SANDBOX/cases"
  cd "$FRIDAY_TEST_SANDBOX/cases"
  git --no-optional-locks apply "$FRIDAY_WEB_TEST_ASSETS/source-tests.patch"

Then run without inherited provider credentials:

  env -i PATH="$PATH" LANG=C.UTF-8 \
    FRIDAY_TEST_NATIVE="$FRIDAY_TEST_NATIVE" \
    FRIDAY_TEST_PROJECT="$FRIDAY_TEST_PROJECT" \
    FRIDAY_TEST_SANDBOX="$FRIDAY_TEST_SANDBOX" \
    "$FRIDAY_TEST_PYTHON" -B "$FRIDAY_WEB_TEST_ASSETS/portable-test-bootstrap.py" -m pytest \
    -q -c /dev/null --rootdir "$PWD" \
    --basetemp "$FRIDAY_TEST_SANDBOX/pytest" \
    ./test_web_input_privacy.py ./test_ordinary_web_journey.py

If pytest is provided separately from the native environment, pass its existing
site-packages directory as FRIDAY_TEST_EXTRA_SITE. No dependency installation
or network is performed by this package.

For source-only packaging checks, FRIDAY_TEST_NATIVE_OVERLAY may name a private
minimal tree of exact afterimages. Root modules and package module paths then
prefer that overlay while loading unchanged dependencies from FRIDAY_TEST_NATIVE.
This import overlay does not verify fresh-exec installation or update behavior.

The bootstrap proves Path.home(), HERMES_HOME, all XDG paths, runtime, gateway
locks and tempfile paths are inside the sandbox BEFORE native imports. It denies
socket/DNS traffic, permits the genuine Linux null character sink for output,
denies other writes outside the sandbox and records isolation and
refused-write evidence there. It does not overwrite the operator's HOME variable.
Run from a fresh interpreter; native modules must not already be loaded.
The pytest cache is disabled and pytest logging remains inside the sandbox.

The 26 credential-input cases are the exact reviewed Sol privacy test bytes.
The two journey cases exercise native AIAgent, SDK serialization, registered
web handlers, child main, Exa response parsing, private spill/read, SQLite close
and reopen, and contextual replay. Model choices and answer text, HTTP responses,
DNS verdict, systemd custody and IPC are explicit fixtures. No real model, web,
Telegram delivery or installed-runtime acceptance is claimed.

web_fixture_config.py contains the unchanged validation_profile function and
three direct helpers extracted from the source-only validation driver. It only
normalizes the synthetic test configuration; it does not launch the driver.
The journey uses FRIDAY_TEST_PROJECT for its published renderer and stores all
observations below pytest's private tmp_path. Original fixture behavior and
all source/citation/history assertions are retained.

Package execution results and exact source/provenance pins are supplied in the
parent WEB-PACKAGE.json. Preserve failed observations as well as passes. A
successful fixture run is offline behavior evidence only. Keep the sandbox
until results are consumed, then remove only that exact disposable directory.
