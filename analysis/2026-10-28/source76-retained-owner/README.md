# Source76: retained-owner compatibility and the next bounded qualification

Source76 is installed and source-accepted in a fresh native process. Its source package changes two worker plugins and no native-tree files. Separately, Root replaced one external A0 runtime file and verified the actual transition with a fresh reader. These are distinct installed-source and runtime-transition facts; neither establishes a successful A0 qualification or user result.

`retained-owner.UNBOUND.patch` fixes the observed owner-context mismatch. A genuine operator initial probe must have empty chat, thread and message fields, the exact operator session key, a native task identifier and a matching session identifier. Only that case compares the retained principal fields. Ordinary work retains exact profile, bot, user, chat, thread and session matching. Container-plan, native, ownership and UNKNOWN-state checks remain in place; retained state is not rewritten.

The previous 1,200-second qualification is closed after the retained-container guard refused it. Its daemon and route were stopped, the operator session was revoked, and no worker container or worker keys were created. `closed1200-consumers.UNBOUND.patch` admits a genuinely separate next operation only after authenticating that closure, its original files and identities, and a changed, bound correction at the same consumer path. The v3 request and once-grant include the closed qualification and corrected consumers; a closed request cannot be reused. Historical 600-second work, the closed 1,200-second clock and the older UNKNOWN user effect are preserved.

`runtime-transition.UNBOUND.patch` shows selected exact functions for the new one-file transition. Its fresh request is tied to the actual preceding runtime and Source75 acceptance. The existing locks, custody, before/after identity checks, consumed intent, rollback and UNKNOWN handling remain. After authenticating the new transition, only the predecessor runtime leaf is projected into the isolated historical reader; other source and native state stays actual. The maintenance envelope is 600 seconds with a 60-second reserve. This patch is an explanatory projection, not an executable maintenance recipe.

`source-runtime-readers.UNBOUND.patch` separates the new source/helper pins from that actual runtime replacement. Current reads use the exact new helper and installed runtime. Runtime normalization accepts only 600/720 and the bound current runtime, delegates the immutable historical conversion, then restores the current reference. Profile720, normalized runtime600, qualification1200/reserve30 and native daemon480/start45/stop20 remain unchanged. Configuration and model settings are unchanged.

The retained-owner source checks passed 24 controls, followed by Root's six checks against actual input variants. The runtime carrier's 35 source-only checks and the closed-operation consumer checks passed separately. Root's actual fresh runtime read took 38.050 seconds. These observations are not a model run or engineering-task acceptance. The existing DSH-produced file, Telegram delivery and contextual continuation remain accepted and were not repeated. A genuine A0-produced engineering file, checked Telegram delivery and contextual continuation are still outstanding at this snapshot.

The four patches are minimal semantic projections with private paths, digests, process identifiers and identity/history dictionaries replaced or omitted. They do not form an installable package and do not reproduce the full installed files. Source-origin hashes and private provenance remain outside the public export. `OBSERVATIONS.json` states the evidence boundaries; `MANIFEST.json` and `SHA256SUMS` cover only these published bytes. Preparing this export made no product, runtime, service, model or Telegram effects.
