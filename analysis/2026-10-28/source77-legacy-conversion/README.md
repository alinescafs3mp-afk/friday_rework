# Source77: legacy conversion and a separate qualification boundary

Source77 is installed and source-accepted in a fresh native process. The package changes two worker plugins, keeps the native tree, and does not reinstall the existing external A0 runtime. This is installed-source acceptance. The new outer `runtime480` completion and a genuine A0 engineering result remain unestablished.

The Source76 qualifier consumed its request and failed before bootstrap because the actual retained configuration still carried the older runtime tuple. The retained input is not silently rewritten. The failure is closed: no model or worker was started, its operator session was revoked, its stage remained absent, and existing services were preserved. The old request, clock and effect cannot be replayed.

`runtime-conversion.UNBOUND.patch` shows the exact changed source modules and the new adapter. The adapter deep-copies input and runs the full historical normalizer before replacing runtime references. It validates runtime home/profile, integer budgets and the complete runtime/launcher/unit tuple. A strict current-config verifier rejects unnormalized legacy input before calling the costly native graph. Only the designated retained predecessor enters the retained converter. Source compatibility propagates through both wrapper layers so the new namespace does not recurse into the former facade. Parent continuity and current native evidence remain distinct authorities.

`closed-conversion-qualification.UNBOUND.patch` authenticates the exact Source76 prebootstrap closure, six consumed files and their identities, the unchanged historical references, and the corrected verifier. A genuinely separate operation uses a v4 request and grant with a fresh clock reference. Monotonic ordering is compared only within one boot; every new clock still validates its actual current boot. The historical closed clock is preserved. Existing qualification1200/reserve30, profile720, normalized runtime600 and native daemon480/start45/stop20 limits remain unchanged.

`qualification-consumers.UNBOUND.patch` and `qualification-preparation.UNBOUND.patch` carry the matching consumer, preparation and checker changes. `source-package.UNBOUND.patch` carries the package producer and adapter transition. Private deployment bindings and identity dictionaries are deliberately omitted. No exported patch is an install recipe or a complete deployable package.

The accepted source checks comprise 59 public-adapter controls and 25 private-glue delta controls. The closed-operation boundary reuses 21 unchanged checks and adds 10 boot-boundary controls. The final source/package gate additionally checks the real built namespace and strict dispatch against actual input variants. These are source-only checks. The profiled actual outer `runtime480` diagnostic was CPU-killed with exit 137 before a completion artifact; its 240-second CPU and 300-second wall limits do not establish successful native completion. Earlier Source76 runtime observations remain scoped to their original bytes and are not promoted to a new completion result.

The genuine DSH-produced file, Telegram delivery and contextual continuation remain accepted and were not repeated. No Source77 product qualification has been run at this snapshot. A genuine A0-produced engineering file, checked Telegram delivery and contextual continuation remain outstanding. Permanent service restoration is being handled separately by Root; this export makes no new service-readiness claim.

These five patches are archival semantic projections of complete before/after module deltas. Paths and digests use stable `UNBOUND` aliases; identity/history dictionaries and native execution identifiers are omitted. They are intended for review, not execution. Source-origin digests, machine identities and private evidence stay outside the public tree. `PROVENANCE.json` lists projection coverage; `OBSERVATIONS.json` separates the accepted facts and open outcomes. `MANIFEST.json` and `SHA256SUMS` cover only the public bytes. Preparing this export changed no repository, installed source, runtime, service, model or Telegram state.
