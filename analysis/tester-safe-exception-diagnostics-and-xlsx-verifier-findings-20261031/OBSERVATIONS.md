# Protected tester exception diagnostics and physical-units verifier findings

A minimal source patch makes a future generic tester exception observable without recording exception messages, tokenized URLs, user text or frame locals. It records a fixed phase and exception category, bounded allowlisted same-source code locations, and validated argument-shape run/plan correlation in an exclusive private file. Those fields confer no operation authority and do not prove dispatch, delivery or a root cause. Diagnostic failure preserves the original REFUSED_OR_UNKNOWN output and exit 2; it cannot resend or repeat an effect. Existing diagnostic files are never overwritten.

The patch changes the existing main exception boundary and phase markers. The existing Runner, Store, API, send and model paths remain byte-identical. Independent source review passed. Twenty distinct synthetic controls cover success and failure behavior, exact status preservation, post-effect exceptions, sensitive exception objects, bounded fields, correlation validation, private directory/file custody, symlinks, existing records, and diagnostic write/fsync failures. The same 20 controls passed in the host source tests and in the installed product's selected isolated Python 3.14.7 environment. These are synthetic dependency tests, not 40 distinct controls or a live authority/observation gate.

The original refusals were preserved. The final selected-native test run exited 0. Temporary fixtures and duplicate source copies were removed after the terminal result; pinned originals and evidence remain.

Root accepted the diagnostic source and selected-native compatibility result. The canonical tester has not yet been replaced. Exact future caller packages, source pins, bindings and mutable authority still require qualification at the integration boundary. Old packages and effects retain their original hashes.
