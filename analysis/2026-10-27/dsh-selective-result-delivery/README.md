# Selective delivery of retained DSH result files

A real DSH coding task produced a retained ZIP. Its contents were independently verified, Friday delivered it through Telegram, and a short follow-up in the same conversation received a correct contextual answer. This establishes the coding core user path for that task; it does not establish full product readiness.

The strict request to return only the ZIP failed: after inspecting several files, Friday called `deliver` without a path selection and the tool attempted all retained files, producing extra attachments. The installed API also ignored explicit delivery paths, as confirmed separately by the offline negative control. One extra attachment was independently observed as a Telegram document while its native receipt remained `UNKNOWN`. That uncertainty is preserved. No worker, artifact creation or delivery was replayed. The native goal assessment also remained unrecorded after invalid assessment arguments; the independent file review is a separate fact.

This source patch makes explicit delivery paths select exact, previously inspected source paths before scheduling. Omitting paths preserves delivery of all retained files. Empty, invalid, duplicate or unknown selections are rejected before scheduling. Existing ownership and retained-job checks remain, and selected `DELIVERED` or `UNKNOWN` attempts remain skipped, including with `retry=true`. Selection does not recollect files, rewrite inspection state or repair old receipts.

`portable-dsh-selective-result-delivery.patch` applies to public commit `7ecdc0a86e0ec13cc6f7511ecf94db135b4e83de`. The base `plugins/friday_rework/result_tool.py` is byte-identical to the installed file used in diagnosis. The resulting file matches the reviewed candidate hash in `source-provenance.json`. This publication contains an analysis patch only: it does not modify the public product tree, install the candidate, change services or activate it automatically.

Root accepted the source delta and reused eight passing method-level offline controls against the changed source AST. Those controls use an in-memory store and transport; the original method reproduced three sends despite a ZIP-only selection. They are not native or Telegram acceptance. Patch replay, exact before/after hashes and Python syntax were checked separately during publication preparation. No fixtures, user inputs, answers, artifact identifiers or private proof contents are published here.

To inspect the code in a separate copy of the pinned public commit, run `git apply --check` and then `git apply` with this patch. Verify the result against the candidate SHA-256 below and use Python `compile()` for a syntax-only check. Installation and future native qualification remain separate work. The strict only-ZIP user contract has not been rerun or accepted with this candidate.
