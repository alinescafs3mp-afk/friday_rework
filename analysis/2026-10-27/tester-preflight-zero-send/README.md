# Tester preflight and zero-send retirement excerpts

UNBOUND analysis of selected mechanisms from one pinned tester source snapshot. These are incomplete source excerpts with unresolved dependencies and placeholder authority values. They are not a runnable tester, installation package, or claim of runtime equivalence.

- `preflight.py`: finite monotonic budget resampled after every guard; pinned bot/peer and empty-webhook checks. `send_preflight_calls.py` shows only the two caller statements that request a 30-second HTTP cap. Original send clocks, acknowledgement and receive windows remain distinct; their implementation is omitted.
- `continuation_guard.py`: the ordinary continuation API keeps its default triple; only the guard requests the optional fourth validated prior value. The historical shortcut supplies `None`, forcing full prior validation when needed. Reuse is within that call; root, credential, cursor, cancellation, cooldown and original-clock checks remain visible. Historical capture predicate and predecessor literals are placeholders.
- `prepared_retirement.py`: exact pristine durable PREPARED/none/zero-attempt state, physical witness absence and protected custody precede retirement. Existing claim reads use a nine-field integrity tuple including group and excluding atime. An absent claim is permitted only for retirement, pinned through its existing protected parent directory; a null claim hash records absence. Default claim reads still refuse absence. Retirement requires named locks, preserves old clocks and UNKNOWN cause, and grants no network effect. STOPPED retirement is historical closure; any future outbound operation needs separate admission and a finite clock through existing consumers. Normal resume is not exported or relaxed.
- `diagnostics.py`: fixed exception/phase categories and at most eight innermost matching own-file frame descriptors out of a bounded traceback walk, including the budget frame. It preserves the first diagnostic without exception text, locals, source, or retry authority. Two historical whitelist names are generalized. The existing durable write code is visible but must not be executed from this analysis package.

Source provenance separates original and exported text/AST hashes. Literal and identifier substitutions preserve only the declared structural correspondence. Five code files comprise ten complete functions plus two noncontiguous send statements; dependencies and surrounding send control flow are deliberately omitted. No private beforeimage is included.

Existing implementation reviews and controls are reused.
