* `associations.py`, `host.py`, `results.py` and `result_tool.py` retain the S445
  result-delivery repair. A single original deadline covers staging, sending and

  A successful external send can only produce its matching single receipt.
  Existing `UNKNOWN` deliveries remain non-replayable. Diagnostics exclude

* `user_worker_join.py` composes the S446 source/native continuity work, the

  Its proof records the distinct stage folder and clock truthfully.
* `worker_provision.py` consumes that coherent source/native bridge.
  `a0_bootstrap.py` retains the accepted cleanup diagnostics. All seven are
  existing plugins; the private project/plugin inventories remain 328/47.
* `tools/source` contains the source producer, existing update template, native
  compatibility wrappers and fresh installed-source checker. They authenticate
  the seven-file descendant and beforeimages instead of rewriting history.
  `tools/cold` shows the authenticated one-shot entry and original-clock carrier;
  `tools/publication` retains the bounded four-link publication transaction,
  current authority/CAS checks and attempted-target rollback reconciliation.

## Export boundary

These are sanitized analysis copies, not drop-in installation files. Deployment
paths, identities and pinned private evidence are replaced with explicit opaque
or synthetic placeholders. No private request, canonical state record, credential,
raw log, user attachment, answer oracle, handoff or session archive is included.
Unexported referenced dependencies are deliberately not supplied as authority.
Source references that were valid in the private installation are intentionally
unbound here; this export does not generate replacement credentials, grants,
hashes or accepted evidence. It must not be used as a runtime updater.

`EXPORT-PROVENANCE.json` distinguishes each exact reviewed private source digest
from its exported digest, records redaction categories/counts and identifies
omissions. Hashes in that manifest are provenance, not live authorization. Exact
private originals and value-by-value redaction maps remain private. The generic
implementation is preserved; changed exported bytes are never described as the
installed bytes. Analysis of deployment-bound joins requires the corresponding
private authenticated graph; it cannot be reproduced from a fabricated fixture.

## Checks and remaining limits

`VALIDATION.json` summarizes completed S445/S446/S447 checks and independent
reviews. Those results apply to their exact original snapshots. They are reused,
not reported as new runtime tests of these redacted copies; overlapping groups
must not be summed. This export separately checks Python syntax without imports,
literal-only redaction consistency, its file hashes and targeted privacy rules.

The old failed cold observation was completed only in memory and was lost during
cleanup. Its original failure, clock and namespace remain unchanged; its resources
were later fully closed. Closure is not qualification, and the original cleanup
cause is unproven. Historical log-delivery uncertainty remains `UNKNOWN`.

The pre-cleanup checkpoint is bounded and best effort. A successfully retained
observation remains `UNSETTLED` / `NOT_READY` after cleanup failure. Existing
consumers still require stopped native ownership, retirement, route and key
settlement, and reject a failed local attempt. This package adds no general
external-settlement bypass or retry. A future cleanup failure could require a
separate exact same-observation consumer repair, without replaying worker/model
effects. IO or size failure cannot guarantee that the observation is retained.
