# Ordinary native delegation source candidate

`native-delegation.patch` extends the intact Hermes delegation path. It is a
source implementation with author offline fixtures, pending independent review
and native acceptance. It does not install or activate a user, mint a worker
grant, start an installation clock, or establish any product journey.

The ordinary source preparer discovers the manifest automatically. This layer
depends on all 21 exact shipped overlays of this candidate. The two repair
layers follow it through exact prerequisite hashes, yielding 24 layers.
Its input hashes describe their final composition, not raw donor files. The
underlying donor remains `781334eea4b9225a3e194faf0c241d9afe218634`.

Before a child opens its dedicated native SessionDB or constructs AIAgent, it
checks the retained authenticated parent, actual user/account/profile/home and
existing protected local credential admission. The constructor receives the
original user/chat/topic identity, a distinct child session, the native parent
session relation, and the original shared iteration budget. Session rows carry
the original account origin before insert; no history row is relabelled later.
The child retains the original run start and deadline even across async delay
or a later parent turn. Observed cancellation remains sticky.

Children remain ordinary leaves. All donor blocked tools stay blocked, including
delegation, memory writes, clarification, cross-platform sending and cron.
Actual child tools are the intersection of the authenticated binding, the
parent's loaded tool names and the donor restrictions. Existing scoped web,
own-workspace file and checked `friday_work`/`friday_result` paths remain useful
when actually present in that intersection. Shell, arbitrary MCP, unrelated
profiles and cloud/credential overrides gain no authority.

The existing registry, lifecycle service and async ledger retain the original
principal and native admission generation. Listing, steering, result access,
completion claims and replay cannot adopt a foreign or old-generation row.
Lifecycle correlation keys include the principal and generation even when two
users have identical session/correlation strings. Existing native interruption,
capacity, depth, daemon execution, history and retirement controls remain in
place; no queue, store, scheduler or worker manager is added.

An unauthenticated startup cannot offer ordinary completion rows. Such rows
remain pending in the existing ledger until an authenticated matching native
scope reaches its existing replay boundary. Legacy rows without retained
authority remain unaccepted for ordinary replay/access; no migration, automatic
rerun or new grant is performed. Administrative shutdown and native exact-child
interruption remain separate from model-facing principal checks.

The normal profile renderer includes `delegate_task` in its protected ordinary
template and exposes the native `delegation` toolset on every configured channel
and CLI. Rendering against the older scope without scoped delegation fails with
`scoped_native_delegation_required`. Existing installed profiles and bindings are
not rewritten. The supported onboarding flow retains its disabled-until-qualified
admission, tool validation and generation checks; child construction and dispatch
still recheck the retained authority. Final composed configuration and real
ordinary execution remain **UNACCEPTED** until independently verified.


The 26 tests execute changed function bodies with explicit synthetic native
boundaries and stdlib data/SQLite fixtures. They cover two users/accounts,
missing and retained authority, generation revocation and re-enable, route/tool
overrides, constructor/session ordering, distinct history relation, original
budgets, cancellation, partial-construction cleanup, registry/lifecycle access,
async ownership and replay. Without an explicit source snapshot the test class
reports a skip; this is not a native passing result. No donor module, worker,
thread pool, SDK/network request, native library or model is executed.

Failed unstarted-child cleanup keeps the existing parent/async/lifecycle handles
and reports `STOP_UNCONFIRMED`; it cannot publish a terminal result or discard
the original stop intent. Only factual native reconciliation can close that
state. Source fixtures inject this failure without creating a native worker.

Independent final composition and real native serial/parallel/async execution,
delivery, list/steer/stop/reconnect, cancellation races and two-user useful
web/file/worker journeys are still **NOT_RUN**. Cancellation uses the donor's
cooperative interruption; these source checks do not establish hard runtime
termination or cleanup. Existing large-history, attachment, skill/browser and
file-update gaps, stopped attempts and all mandatory full gates remain intact.
Source publication and offline checks do not establish runtime or release
acceptance.


The dependent `native-delegation-repair` layer corrects the actual three-value
