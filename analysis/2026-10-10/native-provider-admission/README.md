# Допуск фактических native-провайдеров — исходники для анализа

Статус исходного пакета: **ORIGINAL_REJECTED_F1; CORRECTED_SOURCE_REVIEWED_NOT_RUN**. Сол подготовил [шесть полных исходников](source-index.json): новый `native_provider_admission.py` и пять изменённых потребителей. Экспорт сохранён в `sources/*.py.inert.txt`, инертен и не подключён к installer. Астра остаётся единственным интегратором и владельцем публикации. [Раздельные состояния](outcome.json) сохраняют source, configuration, wiring, offline, live и release.

Пакет реализует проверку для исходного разрыва допуска: проверка списка файлов и адресов в другом процессе не доказывала, куда реально связаны функции будущей библиотеки в вызывающем процессе. Исходники вводят один общий admitted handle: после независимой проверки точного ELF, конструкторов, зависимостей и IFUNC root может отдельно разрешить staged load под исходными clock и FLOCK. До первого candidate API проверяются текущий вызывающий процесс, namespace/link_map, фактические GOT-ячейки, версии и ожидаемые файлы провайдеров; для IFUNC сопоставляется фактический target. Birth, recovery, primitive и join используют тот же handle. Неполные, устаревшие или несовпавшие привязки запрещают вызовы. Это описание исходника, а не наблюдение выполненной загрузки.

Использованы существующая birth seam, исправленный custody и CPU witness; точные C/header/qualification ELF/production ELF/custody сохранены побайтово. Новая native-сборка не выполнялась. Hermes остаётся host, целый Harness — coding, выделенный целый A0 — engineering; архитектура и donor pins не менялись. [Предыдущие опубликованные C/header и состав](../cpu-witness-integration/source-index.json) и [donor notices](../../2026-10-09/incremental-08/THIRD_PARTY_NOTICES.md) сохраняются. Новый helper использует стандартный Python/ctypes, supported glibc inspection API и разбор точных ELF relocation cells; новый supervisor или broker не добавлен.

1553 прежние проверки автора без отказов — 1277 source/ELF/data controls, 173 materialization/reuse и 103 статических load-time проверок. Они не являются независимой или live-приёмкой. Configuration содержит только false templates; политика, clock, текущие process identities и runtime grant не опубликованы. Wiring существует только в исходниках. Реальные провайдеры **UNBOUND**, библиотека **NOT_LOADED**, live **NOT_RUN**, runtime/release acceptance **false**. Первоначальный экспорт создан до завершения независимого ревью. Последующий вердикт и исправленное тело приведены ниже; исходные тела сохранены для анализа.

После принятия исправленного исходника остаются конечная проверка допуска запуска, отдельный законный однократный допуск и реальное доказательство same-caller providers до API вместе с исходной clock/FLOCK/custody/cleanup границей. All30/native15/full42/F6/all11, 277/831 и 38/114 cases/reports, 512 paired calls/deny125, 7 journeys/4 web-контекста сохранены и полностью не приняты. Expiry8/9 остаются EFFECT_REFUSED: E>=D против требуемого C<D, без дополнительного drain window. Старый CPU6 остаётся FAILED_CLOSED_CONSUMED_ORIGIN_UNKNOWN; повтор, сброс бюджета и переоценка запрещены. Прежние plan10 ESTABLISHED, plan11 и GNU9 относятся к своим старым узким снимкам. Trusted raw PROF/soft6-to7 signature не доказывает единственного отправителя SIGXCPU при слиянии стандартных сигналов; latency/guard1/taskwork/child6/aggregate45/tailCPU не доказаны.

Удалены только приватный quality-lock path и его машинная идентичность: по два явных маркера в двух файлах, всего четыре замены. Для всех шести тел проверены обратное восстановление точных байтов и исходного SHA, AST, JSON, относительные ссылки и содержимое публичного subtree. [Правила экспорта](export-policy.json) поясняют намеренно несвязанные маркеры; приватная inverse map хранится отдельно и в публикацию не входит. Остальная логика сохранена целиком. Публикация не разрешает исполнять, устанавливать или загружать эти материалы.

Технические первичные источники из исходного отчёта: [dlopen](https://man7.org/linux/man-pages/man3/dlopen.3.html), [dlinfo](https://man7.org/linux/man-pages/man3/dlinfo.3.html), [dladdr/dladdr1](https://man7.org/linux/man-pages/man3/dladdr.3.html) и [glibc 2.43](https://ftp.gnu.org/gnu/glibc/glibc-2.43.tar.xz). Upstream semantics не доказывает побайтовую идентичность дистрибутивных реализаций.

Независимое ревью исходного пакета выявило F1: исключение от отозванного native handle прерывало finalizer до закрытия локальных FD и записи причины остановки. Запрет native API срабатывал. Астра подготовила исправление: локальная очистка и запись неизвестного состояния продолжаются независимо от отказа getter, а inspection FD освобождаются через внешний finally. Исходный отказ сохранён; исправление принято независимым ревью затронутых путей в том же назначении и исходном бюджете (18 полных сценариев после загрузки и 7 проверок структуры/SHA). Это не новый запуск.

[Исправленное полное тело](fixes/native_fault_controls.py.inert.txt) опубликовано отдельно от исходного неуспешного варианта. [Результат ревью и материализации](review-outcome.json): 48 файлов, 30 Python AST и 221 проверка связей хешей; нативные C/header/ELF сохранены. Для реального запуска остаются контроль вызывающего процесса на всём интервале загрузки и выхода, конечные привязки допуска и отдельное наблюдение. Статусы источников выше относятся к исходному срезу; они не подменяют этот последующий вердикт.
